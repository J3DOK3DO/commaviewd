# Changelog

## [0.0.56-alpha] - 2026-09-26

### What changed

- Keep recording records on the comma for every paired device, so a drive recorded on the car's head unit can be made into a replay from a phone (`recording-records`).
- Build the comma four runtime against the pinned sunnypilot interface used on the test device.
- Recover from invalid video message-queue headers instead of aborting the whole runtime during a reconnect; invalid frames are discarded and logged.
- Prepare route-bound camera-choice and telemetry metadata automatically while driving, without an arm switch or a second copy of the comma's stored camera video.
- Expose current-route metadata health to the paired Android app so Record can reject an incomplete source route.

### Compatibility and test scope

- Paired with Android `0.0.159-alpha` debug test build. The source-recording workflow is bounded to a ten-minute clip and post-drive export; it is not yet a general recording release.
- The 2026-09-26 car attempt with the preceding experimental runtime failed. The paired candidate has passed bench checks, but its recording path still requires a guarded drive test.
- A real drive remains necessary to validate camera switches, source-capture load, Android post-drive MP4 creation, and weak 2.4 GHz hotspot behavior.
